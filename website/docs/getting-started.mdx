# pairmux

**Reliable terminal primitives for AI agents on tmux — and humans can watch, attach, and help in the same live terminal.**

Driving a raw terminal is hard for agents for three separate reasons:

- **Timing.** After sending a command, an agent has no signal for when it is done, so it guesses `sleep N` — and reads half-finished output or wastes time.
- **Information quality.** `capture-pane` shows only the current viewport, mangled with ANSI escapes, spinners, and progress bars, with no exit code and no "is it finished?" signal.
- **Human access.** Headless PTY tools lock humans out entirely, so no one can step in when the agent is stuck.

pairmux is an **ACI (Agent-Computer Interface) layer** on top of tmux that closes all three: blocking calls that return on completion, input, requested conditions, or timeout; a journal that keeps clean full history with exit codes; and native `tmux attach` so a human can take over and hand back.

## Requirements

- **tmux >= 3.2** (for stable `pipe-pane` and pane user-option behavior).
- **macOS or Linux.** On Windows, use WSL.
- No runtime dependencies otherwise — pairmux is a single static Go binary.

## Verify your environment

`pairmux doctor` probes everything pairmux depends on and prints an actionable report:

```bash
pairmux doctor
```

```text
pairmux doctor

✓  tmux        3.7b at /opt/homebrew/bin/tmux (>= 3.2)
✓  state dir   writable: ~/.local/state/pairmux
✓  live probe  zsh: hooks;  bash: hooks-no-C;  fish: hooks;  dash: sentinel
✓  notifier    osascript at /usr/bin/osascript (macOS notifications available)
```

The **live probe** line reports which completion-detection tier each shell reaches. Fish 4+ emits
compatible OSC 133 marks natively; fish without a ready mark degrades to a `$status` sentinel. See
[Concepts](./concepts.md#completion-detection-and-the-idle-backstop).

## Quick start

Every non-interactive command accepts `--json` for a machine-readable [`pairmux.v1` envelope](./cli-reference.md#the-envelope-schema); without it you get a friendly text block. `attach` and `watch` are interactive human interfaces. The examples below show the JSON an agent sees.

### 1. Open a terminal

```bash
pairmux new --name build
```

```json
{"schema":"pairmux.v1","ok":true,"status":"created","terminal":"build","mode":"hooks","next":["pairmux run build \"echo hello\""]}
```

This opens a tmux window, starts capturing its output into a journal, and injects shell integration so completions are detected precisely (`mode: hooks`).

### 2. Run a command and block for an actionable outcome

No `sleep`, no guessing — `run` returns when the command completes, needs input, or reaches its timeout. A completed command includes the exit code and duration:

```bash
pairmux run build "echo hello world"
```

```json
{"schema":"pairmux.v1","ok":true,"status":"done","terminal":"build","mode":"hooks","exit_code":0,"duration_ms":101,"output":"hello world"}
```

### 3. Long-running commands: the run → wait → peek loop

If a command outlives `--timeout` (default 60s), `run` returns `status: running` with the current tail instead of failing. You then keep waiting or look whenever you like:

```bash
pairmux run build "make -j4" --timeout 30s   # -> status: running, with a tail + next steps
pairmux wait build --idle 800                 # block until the shell is truly idle
pairmux peek build                            # read-only snapshot, any time
```

See the [long-running commands guide](./guides/long-running-commands.md).

### 4. Interactive programs

When a command goes quiet on a prompt, pairmux reports `awaiting-input` and tells you exactly how to answer:

```bash
pairmux run deploy "terraform apply"   # -> status: awaiting-input on the [y/N] prompt
pairmux send deploy --text yes --enter
```

Passwords are special: pairmux refuses to guess and hands off to a human. See [interactive programs](./guides/interactive-programs.md) and [human collaboration](./guides/human-collaboration.md).

### 5. Humans jump into the same terminal

```bash
pairmux attach build   # take over the live tmux session
pairmux watch          # live dashboard of every terminal
```
